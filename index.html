使用说明 人脸情绪识别算法 旋律曲调情绪算法 推荐策略 性能与实测

一、使用说明

整个系统跑在浏览器里：图片、视频、摄像头画面不会上传到任何服务器，识别、音频分析与推荐全部在前端本地完成。

1. 四种人脸输入方式

方式操作步骤适用场景注意
上传图片点「选择本地图片」，或直接点下方演示人脸库任一张评测、演示、单次识别单人正脸，光照均匀，脸占画面 1/4 以上
打开视频点「打开视频文件」选择本地 mp4/webm，自动逐帧识别分析影视片段里的人物情绪变化识别频率约 12 FPS，可随时暂停
实时摄像头点「开启摄像头」并授权，正脸对准镜头实时互动、情绪跟随切歌需 localhost 或 https 环境才能调用摄像头
屏幕视频点「共享屏幕 / 窗口」，选择正在播放视频的窗口演示「看剧时自动配乐」共享整个屏幕时，人脸需占画面较大比例

2. 推荐流程

  1. 识别人脸情绪：画面中出现人脸后，右侧实时显示 7 类情绪概率与二维情绪坐标。
  2. 分析本地曲库：首次进入自动分析 12 首本地曲目（每首约 0.1–0.25 秒），结果缓存到 localStorage，下次秒开。
  3. 选择推荐策略：情绪共鸣 / 情绪调节 / 混合策略，切换后推荐列表立即重排。
  4. 播放与反馈：点「播放」试听；点 ♡ 喜欢或 ⏭ 跳过，会即时更新你的情绪画像并影响后续排序。画像与反馈会存到 localStorage，刷新后仍在；想从零开始就点「重置画像」。
  5. 在线曲库：点「搜索在线曲目」按当前情绪关键词检索 Audius 开放曲库；点播后会用同一套本地算法旁路分析其真实旋律特征。

二、人脸情绪识别算法

采用「检测 → 关键点 → 表情分类 → 晚期融合 → 时序平滑」的经典五段式流水线，全部本地推理，单帧 20–60 ms。

1. 流水线总览

输入帧
  │
  ├─① TinyFaceDetector（SSD 单阶段检测，输入可切 416/320/224）
  │     └─▶ 人脸框 bbox + 检测置信度（NMS 后取最高分）
  │
  ├─② 68 点关键点回归（tiny landmark）
  │     └─▶ 6 维几何特征：EAR / 嘴角上扬 / 眉高比 / 眉心距 / 张口度 / 嘴宽比
  │
  ├─③ FaceExpressionNet（mini-Xception）
  │     └─▶ 7 类 softmax：neutral happy sad angry fearful disgusted surprised
  │
  ├─④ 晚期融合：P = 0.78·P_cnn + 0.22·P_geo
  │
  └─⑤ EMA 平滑 + 主导类滞回 ──▶ 稳定情绪标签 + 置信度

2. 人脸检测：TinyFaceDetector（SSD + 深度可分离卷积）

单阶段检测器（Single Shot MultiBox Detector）。骨干网络用深度可分离卷积（depthwise + pointwise）替代普通卷积，把参数量与乘加次数压到 1/8 左右；在多个尺度特征图上以 anchor 方式直接回归「人脸框偏移 (dx, dy, dw, dh)」与「置信度」，最后做 NMS 去重。

损失函数（训练期）: L = L_conf(cls, c) + λ·L_box(t, t*)      IoU 阈值 = 0.3，λ ≈ 2
推理期: 输入缩放到 N×N（N 取 416/320/224/192）→ 前向 → 置信度 > 阈值 的 anchor → NMS → 取最高分人脸

工程参数：inputSize 可切三档（WebGL：416 / 320 / 224，CPU：320 / 256 / 192）、scoreThreshold（WebGL 0.35 / CPU 0.4，CPU 上调是因为低分辨率下弱证据更容易被放大成错判）、模型权重仅 193 KB。因为只在固定分辨率的特征图上做一次前向，所以检测延迟与画面内容无关，是恒定 O(H·W·C) 的卷积开销。

3. 68 点关键点与几何特征

tiny landmark 网络在检测框内回归 68 个面部关键点，用于计算可解释的面部动作单元（AU）近似量：

几何特征定义情绪含义
眼睛纵横比 EAREAR = (|p₂−p₆| + |p₃−p₅|) / (2|p₁−p₄|)睁眼程度：惊讶/恐惧时显著增大
嘴角上扬 smiles = (y_唇中 − y_嘴角) / 瞳距s > 0 为嘴角上翘，开心核心特征
眉高比 browHeight(y_眼上缘 − y_眉) / 瞳距眉毛抬高：惊讶、恐惧（AU1+AU2）
眉心距 innerBrowGap|p₂₁ − p₂₂| / 瞳距皱眉收拢：愤怒、厌恶（AU4）
张口度 mouthOpen|p₆₂ − p₆₆| / 瞳距惊讶、呼喊；闭唇紧压则偏愤怒
嘴宽比 mouthWidth|p₄₈ − p₅₄| / 瞳距大笑时嘴角外拉（AU12）

4. 表情分类：FaceExpressionNet（mini-Xception）

在 FER 数据集训练的轻量卷积网络，采用 mini-Xception 结构：深度可分离卷积 + 残差连接 + 全局平均池化，最后 softmax 输出 7 类概率。模型仅 329 KB，输入 48×48 灰度人脸，单帧 < 5 ms。

P_cnn = softmax(W·GAP(ResBlock(DepthwiseConv(x))) + b) ∈ R⁷
类别 = { neutral, happy, sad, angry, fearful, disgusted, surprised }

5. 晚期融合：为什么还要几何规则

CNN 在侧脸、逆光、口罩、遮挡时会系统性地偏向中性。几何特征虽然噪声大，但在正脸条件下对「笑」「皱眉」「张嘴」非常敏感且方向明确，因此取两者加权：

P_fused[k] = 0.78 · P_cnn[k] + 0.22 · P_geo[k],   k ∈ 7 类,   Σ P_fused = 1

P_geo 由可解释规则归一化得到，例如：
  happy    = 0.62·smileN + 0.24·mouthWidthN + 0.14·(0.5 + 0.5·openN)
  angry    = 0.52·knitN  + 0.28·pressN      + 0.20·(1 − smileN)·knitN
  surprised= 0.46·raiseN + 0.32·wideN       + 0.22·openN

6. 时序平滑与标签稳定

逐帧独立分类会出现「开心 → 中性 → 开心」的抖动。用指数滑动平均（EMA）做低通滤波，再加主导类滞回：

S_t = α · P_fused,t + (1 − α) · S_{t−1},      α = 0.55
切换主导类条件: S_t[k'] > S_t[k_current] + 0.10   （滞回阈值，避免临界抖动）

7. 复杂度

检测 O(H·W·C·k²) ≈ 常量（H·W 由档位固定，与画面内容无关）
关键点 O(N_pts · C)
分类 O(C² · N_block)
整链单帧 20–60 ms（WebGL） / 300–800 ms（CPU 回退，输入已降为 224），12 FPS 采样下 WebGL 路径 CPU 占用 < 30%

三、旋律曲调情绪识别算法

对本地音频做纯信号处理（不依赖任何云端服务或预训练模型），提取「快慢、节奏、频率高低、调式」四类线索，映射到二维情绪平面。

1. 预处理

  • 多声道下混为单声道：x[n] = (1/C)·Σ x_c[n]
  • 线性插值重采样到 11025 Hz：情绪相关的音色/节奏信息集中在 5 kHz 以内，降采样使 FFT 计算量降到 44.1 kHz 的 1/4。

2. 短时傅里叶变换（STFT）

X_t[k] = Σ_{n=0}^{N−1} x[t·H + n] · w[n] · e^(−j2πkn/N)
N = 2048（约 186 ms 窗长）, H = 256（约 23 ms 帧移）, w = 汉宁窗, 频率分辨率 5.38 Hz

3. 节奏：对数谱通量起音检测 + 自相关测速

先对每帧幅度谱做尺度无关的对数压缩，再取正向差分求和，得到起音强度包络（对弱起音也敏感，且不会被响亮的持续声部淹没）：

L_t[k] = ln(1 + 99·|X_t[k]| / max_k|X_t[k]|)
Δ_t   = Σ_k max(0, L_t[k] − L_{t−1}[k])            ← 谱通量
e_t   = max(0, Δ_t − 1.15·mean(Δ_{t−8..t}))        ← 去局部均值后半波整流，再归一化

对包络做自相关，峰位置即「拍周期」，再叠加两个经典技巧：

r(τ) = Σ_t e_t·e_{t+τ} / Σ_t e_t²                    （归一化自相关，τ 为帧数）
候选 BPM = 60·f_env / τ,   f_env = 11025/256 ≈ 43.07 Hz
① 对数高斯节奏先验：w(bpm) = exp(−½·(log₂(bpm/112)/0.9)²)   （人类节拍中心 ≈ 110–120 BPM）
② 抛物线插值细化：τ* = τ + ½(y₋₁ − y₊₁)/(y₋₁ − 2y₀ + y₊₁)   （把量化误差从 3% 降到 <0.5%）
③ 倍频消歧：若 r(τ/2) ≥ 0.33·r(τ) 且对应 BPM ≤ 180，则把节奏层级上移到"拍"层
   （4/4 里底鼓在 1、3 拍、军鼓在 2、4 拍，会让自相关在"两拍"处更强，这是最常见的倍频误判）

4. 调式：色度向量 × Krumhansl 调性轮廓

只取 120–2000 Hz 的谱局部峰（避免低频鼓点和高频齿音污染），按对数频率折叠到 12 个音级得到色度向量，再与 Krumhansl-Kessler 大/小调轮廓做皮尔逊相关，取 12 个旋转中的最大值：

chroma[pc] += ln(1 + 60·|X_t[k]|),   pc = round(12·log₂(f/440) + 69) mod 12
r_major = max_r  corr(roll(chroma, r), KK_major)
r_minor = max_r  corr(roll(chroma, r), KK_minor)
调式分 modeScore = r_major − r_minor  （>0 大调，<0 小调）；调性强度 tonality = max(r_major, r_minor)

5. 频率高低：谱质心与频段能量比

谱质心  C = Σ_k f_k·|X_t[k]| / Σ_k |X_t[k]|          （音色"亮度"，单位 Hz）
低频比  R_low  = E(<250 Hz) / E_all                （贝斯/底鼓重量）
高频比  R_high = E(>2 kHz)  / E_all                （镲片/齿音/失真，尖锐感来源）
响度    RMS_dB = 20·log₁₀(mean_t RMS_t)
起音密度 onsetDensity = 有效起音峰数 / 时长（个/秒）  ← "节奏密集程度"，与 BPM 互补

6. 特征归一化

特征归一化公式情绪含义
速度 bpmNclamp((BPM−56)/102)快慢 → 唤醒度
亮度 brightNclamp((C−800)/2400)音色明暗 → 效价/唤醒
响度 energyNclamp((RMS_dB+32)/26)能量感
起音密度 onsetNclamp((density−0.6)/4.0)节奏密度
调式 modeNclamp(0.5 + 2·modeScore)大调↔小调 → 效价（主导项）
调性强度 tonalityNclamp(tonality)调性感是否清晰
高频比 highNclamp((R_high−0.02)/0.35)尖锐/刺激感

7. 映射到情绪平面（权重由标注曲目最小二乘标定）

Arousal = 0.000 + 0.780·bpmN + 0.030·brightN + 0.230·energyN + 0.150·onsetN + 0.080·modeN + 0.020·tonalityN + 0.020·highN
Valence = −0.010 + 0.020·bpmN + 0.390·brightN + 0.020·energyN + 0.090·onsetN + 0.670·modeN + 0.020·tonalityN + 0.020·highN

权重由 12 首「BPM / 调式 / 情绪标签已知」的标注曲目做带下界约束的最小二乘回归得到（scipy.optimize.lsq_linear，下界 0.02 保证每个特征都保留可解释的正向贡献），标定脚本见 tools/calibrate.py，复现命令 node tools/test_analyzer.js。

8. 复杂度

STFT:   O(N_frames · N log N) = O(N log N)，N 为采样点数
其余:   每帧 O(N)（通量/色度/质心/频段能量一遍扫完）
ACF:    O(L_max · N_frames)，L_max ≈ 47 帧
实测:   25 秒曲目 92–236 ms（单线程 JS），一次性分析后写入 localStorage 缓存

四、推荐算法与策略

1. 目标情绪点的计算

不直接用最大类，而是用整条 7 类概率分布投影到 VA 平面（期望值），这样"70% 开心 + 25% 平静"和"95% 开心"会得到不同的目标点：

V_target = Σ_k P[k]·V_k ,   A_target = Σ_k P[k]·A_k

再按策略与"调节目标"混合：
  情绪共鸣 congruent : T = T_cong
  情绪调节 regulate  : T = 0.25·T_cong + 0.75·T_reg     （T_reg 见下表）
  混合策略 mixed     : T = 0.70·T_cong + 0.30·T_reg
识别到情绪共鸣（陪着）情绪调节（牵引到）
开心明亮大调、快板高效价 + 中高唤醒（保持好状态）
悲伤小调、慢速、低亮度V 0.64 / A 0.46（先共情、再轻推向上）
愤怒失真、强节奏、高响度V 0.52 / A 0.30（降唤醒、泄压）
惊讶离调、跳跃、尖锐V 0.60 / A 0.52（收敛刺激）
恐惧暗色、悬疑、不稳定V 0.58 / A 0.32（给安全感）
平静中速、通透V 0.60 / A 0.46（维持）

2. 内容相似度（加权欧氏距离）

d(T, S) = √( w_V·(V_T − V_S)² + w_A·(A_T − A_S)² ) / √(w_V + w_A),   w_V = 1.0, w_A = 0.8
sim(T, S) = 1 − d(T, S) ∈ [0, 1]
效价权重更大：调式（大/小调）对情绪效价的影响比速度对唤醒度的影响更直接、更稳定。

3. 多样性重排：MMR

纯按相似度排序容易给出 6 首几乎一样安静的歌。用 Maximal Marginal Relevance 在「相关」与「不重复」之间取平衡：

MMR(S_i) = λ · score(S_i) − (1 − λ) · max_{S_j ∈ 已选} sim(S_i, S_j),   λ = 0.72
每次挑 MMR 最大的进榜，再迭代——保证前 6 首既贴近目标情绪，又在 VA 平面上铺开。

4. 在线反馈学习（画像更新）

score = 0.78·sim(T, S) + 0.22·sim(Profile, S) + 0.09·feedback[S]
点 ♡（喜欢）：Profile ← Profile + 0.35·(S − Profile)
点 ⏭（跳过）：Profile ← Profile − 0.18·(S − Profile)
画像权重随交互次数增长，最多占 22% 的影响，避免几首歌就把推荐带偏。

画像、反馈记录与所选策略都写入 localStorage（键 emotionMusic.profile.v1），刷新或重开浏览器后继续生效，不必每次重新「认识」你。点「重置画像」清空画像与反馈记录并立刻重排推荐，所选策略作为界面偏好保留。

结论有两处反直觉。其一，输入越大并不越准：320 的检出（13）反而少于 256（14）——TinyFaceDetector 的 anchor 只覆盖一定的人脸尺度区间，把本就占满画面的脸再放大，反而掉出可检出范围。其二，没有放宽检测阈值：把 scoreThreshold 从 0.4 降到 0.35 确实能把最后一张补齐，但那一张会被高置信度错判成「开心」，对一个主打准确率的系统来说，给错答案比明确说「未检出」更伤可信度，所以保留 0.4。纯 CPU 环境因此默认「均衡」，比「高精度」快 26%、检出还多一张。档位选择会记住，下次进来沿用。
