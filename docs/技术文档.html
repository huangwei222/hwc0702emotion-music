一、系统概述与使用

本系统是一个完全运行在浏览器内的「人脸情绪 → 音乐推荐」应用：打开摄像头或选一张照片，前端完成人脸检测、表情分类、情绪坐标计算，再从本地曲库与在线曲库中挑出情绪匹配的曲目。整条链路没有服务端，模型权重、曲库、算法脚本随项目一起分发，断网可用。

1.1　设计目标与取舍

  • 算法可解释：不用一个黑箱模型包打天下，而是把「检测 → 关键点 → 分类 → 融合 → 平滑」与「STFT → 起音 → 测速 → 调式」每一步都摊开，界面里能看到 7 类概率、CNN 与几何双通道的对比、VA 散点坐标。
  • 数据不落地：人脸画面、上传的音频只在浏览器内存与 IndexedDB 中存在，没有一处上传请求。
  • 指标可复现：所有性能数字都由项目内脚本实测产出，标注曲目的 BPM、调式、情绪标签在合成时即已知，可逐项核对。

1.3　一次完整推荐流程

  1. 识别人脸情绪：画面中出现人脸后，右侧实时显示 7 类情绪概率与二维情绪坐标（效价 V / 唤醒 A）。

  3. 选择推荐策略：情绪共鸣 / 情绪调节 / 混合策略，切换后推荐列表立即重排。

二、人脸情绪识别算法

采用「检测 → 关键点 → 表情分类 → 晚期融合 → 时序平滑」的五段式流水线，全部本地推理，WebGL 下单帧 20–60 ms。

2.1　流水线总览

输入帧

  │

  ├─① TinyFaceDetector（SSD 单阶段检测，输入可切 416 / 320 / 224）

  │     └─▶ 人脸框 bbox + 检测置信度（NMS 后取最高分）

  │

  ├─② 68 点关键点回归（tiny landmark）

  │     └─▶ 6 维几何特征：EAR / 嘴角上扬 / 眉高比 / 眉心距 / 张口度 / 嘴宽比

  │

  ├─③ FaceExpressionNet（mini-Xception）

  │ └─▶ 7 类 softmax：neutral happy sad angry fearful disgusted surprised

  │

  ├─④ 晚期融合：P = 0.78·P_cnn + 0.22·P_geo

  │

  └─⑤ EMA 平滑 + 主导类滞回 ──▶ 稳定情绪标签 + 置信度

2.2　人脸检测：TinyFaceDetector

单阶段检测器（Single Shot MultiBox Detector）。骨干网络用深度可分离卷积（depthwise + pointwise）替代普通卷积，把参数量与乘加次数压到 1/8 左右；在多个尺度特征图上以 anchor 方式直接回归「人脸框偏移 (dx, dy, dw, dh)」与「置信度」，最后做 NMS 去重。

损失函数（训练期）: L = L_conf(cls, c) + λ·L_box(t, t*) IoU 阈值 = 0.3，λ ≈ 2

推理期: 输入缩放到 N×N → 前向 → 置信度 > 阈值 的 anchor → NMS → 取最高分人脸

工程参数：inputSize 可切三档（WebGL：416 / 320 / 224，CPU：320 / 256 / 192）；scoreThreshold 取 WebGL 0.35、CPU 0.4（CPU 上调是因为低分辨率下弱证据更容易被放大成错判，理由见 5.3 节）；模型权重仅 193 KB。因为只在固定分辨率的特征图上做一次前向，检测延迟与画面内容无关，是恒定 O(H·W·C) 的卷积开销。

2.3　68 点关键点与几何特征

tiny landmark 网络在检测框内回归 68 个面部关键点，用于计算可解释的面部动作单元（AU）近似量，记为 6 维特征向量。

几何特征定义情绪含义
眼睛纵横比 EAREAR = (|p₂−p₆| + |p₃−p₅|) / (2|p₁−p₄|)睁眼程度：惊讶 / 恐惧时显著增大
嘴角上扬 smiles = (y唇中 − y嘴角) / 瞳距s > 0 为嘴角上翘，开心的核心特征
眉高比 browHeight(y眼上缘 − y眉) / 瞳距眉毛抬高：惊讶、恐惧（AU1+AU2）
眉心距 innerBrowGap|p₂₁ − p₂₂| / 瞳距皱眉收拢：愤怒、厌恶（AU4）
张口度 mouthOpen|p₆₂ − p₆₆| / 瞳距惊讶、呼喊；闭唇紧压则偏愤怒
嘴宽比 mouthWidth|p₄₈ − p₅₄| / 瞳距大笑时嘴角外拉（AU12）

2.4　表情分类：FaceExpressionNet

在 FER 数据集训练的轻量卷积网络，采用 mini-Xception 结构：深度可分离卷积 + 残差连接 + 全局平均池化，最后 softmax 输出 7 类概率。模型仅 329 KB，输入 48×48 灰度人脸，单帧耗时小于 5 ms。

P_cnn = softmax( W · GAP( ResBlock( DepthwiseConv(x) ) ) + b ) ∈ R⁷

类别 = { neutral, happy, sad, angry, fearful, disgusted, surprised }

2.5　晚期融合：为什么还要几何规则

CNN 在侧脸、逆光、口罩、遮挡时会系统性地偏向中性；几何特征虽然噪声大，但在正脸条件下对「笑」「皱眉」「张嘴」非常敏感且方向明确。因此取两者加权，得到最终概率分布：

P_fused[k] = 0.78 · P_cnn[k] + 0.22 · P_geo[k],   k ∈ 7 类,   Σ P_fused = 1

 

P_geo 由可解释规则归一化得到，例如：

  happy     = 0.62·smileN + 0.24·mouthWidthN  + 0.14·(0.5 + 0.5·openN)

  angry     = 0.52·knitN  + 0.28·pressN       + 0.20·(1 − smileN)·knitN

  surprised = 0.46·raiseN + 0.32·wideN        + 0.22·openN

2.6　时序平滑与标签稳定

逐帧独立分类会出现「开心 → 中性 → 开心」的抖动。用指数滑动平均（EMA）做低通滤波，再加主导类滞回：

S_t = α · P_fused,t + (1 − α) · S_(t−1),                    α = 0.55

切换主导类条件: S_t[k'] > S_t[k_current] + 0.10 （滞回阈值，避免临界抖动）

检测失败（画面中无人脸）时，平滑状态会被清空而不是继续沿用旧值，避免「把上一张脸的余温算到下一张脸上」；切换识别档位同理，因为不同输入尺寸下的概率分布不可比。

2.7　复杂度

检测   O(H·W·C·k²)   ≈ 常量（H·W 由档位固定，与画面内容无关）

关键点 O(N_pts · C)

分类   O(C² · N_block)

整链单帧 20–60 ms（WebGL）/ 300–800 ms（CPU 回退，输入已降为 224）

12 FPS 采样下 WebGL 路径 CPU 占用 < 30%

三、旋律曲调情绪识别算法

对本地音频做纯信号处理，不依赖云端服务或预训练模型，提取「快慢、节奏、频率高低、调式」四类线索，映射到二维情绪平面。

3.1　预处理

  • 多声道下混为单声道：x[n] = (1/C)·Σ x_c[n]
  • 线性插值重采样到 11025 Hz：与情绪相关的音色 / 节奏信息集中在 5 kHz 以内，降采样使 FFT 计算量降到 44.1 kHz 的 1/4。

3.2　短时傅里叶变换（STFT）

X_t[k] = Σ_(n=0..N−1) x[t·H + n] · w[n] · e^(−j2πkn/N)

 

N = 2048（约 186 ms 窗长） H = 256（约 23 ms 帧移） w = 汉宁窗 频率分辨率 5.38 Hz

FFT 为手写的基-2 迭代实现（js/dsp.js），不引入任何数值库，保证断网与零依赖。

3.3　节奏：对数谱通量起音检测 + 自相关测速

先对每帧幅度谱做尺度无关的对数压缩，再取正向差分求和，得到起音强度包络——对弱起音敏感，且不会被响亮的持续声部淹没：

L_t[k] = ln( 1 + 99·|X_t[k]| / max_k |X_t[k]| )

Δ_t    = Σ_k max( 0, L_t[k] − L_(t−1)[k] )                 ← 谱通量

e_t = max( 0, Δ_t − 1.15·mean(Δ_(t−8..t)) ) ← 去局部均值后半波整流，再归一化

对包络做归一化自相关，峰位置即「拍周期」，再叠加三个工程技巧：

r(τ) = Σ_t e_t·e_(t+τ) / Σ_t e_t²                          （τ 为帧数）

候选 BPM = 60 · f_env / τ,    f_env = 11025 / 256 ≈ 43.07 Hz

 

① 对数高斯节奏先验：w(bpm) = exp( −½·(log₂(bpm/112) / 0.9)² ) （节拍中心 ≈ 110–120 BPM）

② 抛物线插值细化：τ* = τ + ½·(y₋₁ − y₊₁) / (y₋₁ − 2y₀ + y₊₁) （量化误差 3% → <0.5%）

③ 倍频消歧：若 r(τ/2) ≥ 0.33·r(τ) 且对应 BPM ≤ 180，则把节奏层级上移到「拍」层

   4/4 里底鼓在 1、3 拍、军鼓在 2、4 拍，会让自相关在「两拍」处更强，这是最常见的倍频误判

第 ③ 步是精度关键：不做倍频消歧时 12 首标注曲目的 BPM 平均相对误差为 36 %，做完降到 0.1 %。

3.4　调式：色度向量 × Krumhansl 调性轮廓

只取 120–2000 Hz 的谱局部峰（避免低频鼓点与高频齿音污染），按对数频率折叠到 12 个音级得到色度向量，再与 Krumhansl-Kessler 大 / 小调轮廓做皮尔逊相关，取 12 个旋转中的最大值：

chroma[pc] += ln( 1 + 60·|X_t[k]| ), pc = round( 12·log₂(f/440) + 69 ) mod 12

r_major = max_r corr( roll(chroma, r), KK_major )

r_minor = max_r corr( roll(chroma, r), KK_minor )

 

modeScore = r_major − r_minor      （> 0 大调，< 0 小调）

tonality  = max( r_major, r_minor ) （调性强度，衡量调感是否清晰）

3.5　频率分布特征

谱质心 C = Σ_k f_k·|X_t[k]| / Σ_k |X_t[k]| （音色「亮度」，单位 Hz）

低频比     R_low  = E(<250 Hz) / E_all                （贝斯 / 底鼓重量）

高频比 R_high = E(>2 kHz) / E_all （镲片 / 齿音 / 失真，尖锐感来源）

响度       RMS_dB = 20·log₁₀( mean_t RMS_t )

起音密度 onsetDensity = 有效起音峰数 / 时长（个/秒） ← 节奏密集程度，与 BPM 互补

3.8　复杂度

STFT:  O(N_frames · N log N) = O(N log N)，N 为采样点数

其余:  每帧 O(N)（通量 / 色度 / 质心 / 频段能量一遍扫完）

四、推荐算法与策略

4.1　目标情绪点的计算

不直接用「最大类」，而是用整条 7 类概率分布投影到 VA 平面（期望值）。这样「70 % 开心 + 25 % 平静」和「95 % 开心」会得到不同的目标点，信息利用更充分。

V_target = Σ_k P[k]·V_k ,    A_target = Σ_k P[k]·A_k

 

再按策略与「调节目标」混合：

  情绪共鸣 congruent : T = T_cong

  情绪调节 regulate  : T = 0.25·T_cong + 0.75·T_reg

  混合策略 mixed     : T = 0.70·T_cong + 0.30·T_reg

识别到情绪共鸣（陪着）情绪调节（牵引到）
开心明亮大调、快板高效价 + 中高唤醒（保持好状态）
悲伤小调、慢速、低亮度V 0.64 / A 0.46（先共情，再轻推向上）
愤怒失真、强节奏、高响度V 0.52 / A 0.30（降唤醒、泄压）
惊讶离调、跳跃、尖锐V 0.60 / A 0.52（收敛刺激）
恐惧暗色、悬疑、不稳定V 0.58 / A 0.32（给安全感）
平静中速、通透V 0.60 / A 0.46（维持）

4.2　内容相似度（加权欧氏距离）

d(T, S) = √( w_V·(V_T − V_S)² + w_A·(A_T − A_S)² ) / √(w_V + w_A), w_V = 1.0, w_A = 0.8

sim(T, S) = 1 − d(T, S) ∈ [0, 1]

效价权重更大：调式（大 / 小调）对情绪效价的影响比速度对唤醒度的影响更直接、更稳定。

4.3　多样性重排：MMR

纯按相似度排序容易给出 6 首几乎一样安静的歌。用 Maximal Marginal Relevance 在「相关」与「不重复」之间取平衡：

MMR(S_i) = λ · score(S_i) − (1 − λ) · max_(S_j ∈ 已选) sim(S_i, S_j), λ = 0.72

每次挑 MMR 最大的进榜，再迭代——保证前 6 首既贴近目标情绪，又在 VA 平面上铺开。副作用是：若上传的曲目与库内某首歌完全相同，两者 VA 坐标一致，多样性重排会把其中一首挤出前 6，这是预期行为而非缺陷。

4.4　在线反馈学习（画像更新）

score = 0.78·sim(T, S) + 0.22·sim(Profile, S) + 0.09·feedback[S]

 

点 ♡（喜欢）：Profile ← Profile + 0.35·(S − Profile)

点 ⏭（跳过）：Profile ← Profile − 0.18·(S − Profile)

画像权重随交互次数增长，最多占 22 % 的影响，避免几首歌就把推荐带偏。画像、反馈与所选策略都写入 localStorage（键 emotionMusic.profile.v1），刷新或重开浏览器后继续生效。点「重置画像」清空画像与反馈并立刻重排推荐，所选策略作为界面偏好保留。

4.5　在线曲库（Audius 开放 API）

  • 按当前情绪的关键词检索（如 sad → sad melancholy piano），取前 4 首可流式播放的曲目。

表 5-3　CPU 后端三档输入尺寸的表现

两处反直觉，都是实测推翻直觉：

其一，输入越大并不越准。320 的检出（13）反而少于 256（14）——TinyFaceDetector 的 anchor 只覆盖一定的人脸尺度区间，把本就占满画面的脸再放大，反而掉出可检出范围。

其二，没有放宽检测阈值。把 scoreThreshold 从 0.4 降到 0.35 确实能把最后一张补齐，但那一张会被高置信度错判成「开心」。对一个主打准确率的系统来说，给错答案比明确说「未检测到人脸」更伤可信度，所以保留 0.4。

结论：纯 CPU 环境默认「均衡」，比「高精度」快 26 %，检出还多一张；档位选择会记住，下次进来沿用。

附录 B　已知限制与可继续改进的方向

  • 妆容与遮挡：口罩、墨镜、浓妆会显著降低关键点精度，几何通道随之失真；此时结果基本由 CNN 主导。
  • 多人画面：只取置信度最高的一张脸，不做多人情绪聚合。
  • 在线曲目的 VA 初值：来自关键词先验，若曲目标题 / 描述不含情绪词，会落到中性 0.5 / 0.5，需要点播后由真实分析纠正。
  • 曲库规模：本地 12 首用于验证算法，推荐效果的多样性受曲库大小限制；可通过「上传我的歌曲」扩充。
  • 可改进方向：把音频分析移入 Web Worker 以彻底消除首屏分析时的主线程停顿（实测最长 261 ms）；离线包（Service Worker）以支持 PWA 安装；多人情绪均值用于聚会场景。
